# 客户端配置与离线表结构

这两个 JSON 文件被编译进程序，用于 `/master-schema` 及旧 APK 快照来源校验，因此随源码保留。

- `master-schema-global.json`：国际服 Android 1.0.1，240 张表；字段来源为客户端 IL2CPP 元数据。
- `master-schema-jp.json`：日服 Android 1.0.3，235 张表；字段类型从解密的 Master JSON 推断。

文件包含表结构和 APK 摘要，不包含账号凭据或完整游戏记录。它们是特定客户端构建的结构索引，不表示线上最新版。线上 Master 版本及表数据通过配置的 Sirius 快照存储读取。

`jp-client.json` 集中保存日服 Android 客户端版本、服务地址、协议路径、CDN 认证和 Master key/IV。这些是从已核对客户端取得的共享常量，由程序启动时读取；镜像内置一份初始配置，并可下载最新版本；不包含账号或部署者的 API Key。版本检测只读，不修改此文件；适配新客户端时须一并核对版本、凭据、Master 常量和 APK 快照来源。

维护时在同一个 PR 核对相关字段，验证后合并。Docker 启动或重启时拉取 main 上的最新 JSON，校验并原子替换持久缓存；失败保留上一份配置。参数变化无需重新编译。新配置要求的协议文件若不存在，拒绝应用该配置，需先更新程序或协议。

独立二进制默认读取启动目录的 `data/jp-client.json`，也可通过 `PENLIGHT_CLIENT_CONFIG` 指定路径；默认文件不存在时使用构建内置的兜底配置。显式指定的文件不存在或格式错误会启动失败。支持显式环境覆盖以便本地适配测试；正式部署应省略这些覆盖，以免掩盖 JSON 更新。
