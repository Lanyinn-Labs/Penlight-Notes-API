# 开发计划

## 第一阶段：服务基础设施

状态：已完成。

- HTTP 服务、日志与优雅关闭
- 国际服与日服独立配置
- 健康检查、版本查询与区服状态查询
- API Key 认证与统一错误响应
- Docker 部署、持续集成与接口测试
- APK 文件清单与摘要工具

## 第二阶段：国际服协议接入

状态：待开发。

- 解析 AndroidManifest，确认包名、`versionName` 与 `versionCode`
- 分析 Unity IL2CPP 文件，确认客户端版本、服务地址、请求路径与数据模型
- 验证认证、会话、序列化、压缩、加密及版本协商流程
- 实现游戏服务客户端与应用信息接口

协议实现以 Our Notes 客户端及实际通信数据为依据。与其他游戏的协议兼容性需单独验证。

## 第三阶段：游戏数据接口

状态：待协议接入完成。

- 基础数据与资源版本查询
- 卡牌、歌曲、活动及排行接口
- 用户数据接口
- 按区服隔离的会话与缓存
- 请求超时、缓存有效期与并发请求合并

具体接口及字段以协议分析结果为准。

## 第四阶段：日服接入

状态：待获取日服客户端。

- 生成安装包检查报告，分析包名、程序集与资源结构
- 比较国际服与日服的协议差异
- 实现日服独立地址、版本与认证配置
- 验证会话隔离、缓存隔离及接口行为

## 分析资料管理

原始安装包、解包文件及认证凭据不纳入版本控制。本地分析产物按区服存放于 `artifacts/{region}/`；经整理的结构说明与分析记录存放于 `docs/`。
